# Invoice Engine

Version: 1.0

Status: Approved Requirements Baseline (Frozen)

Baseline Date: 20 July 2026

## Purpose

This document defines invoice behaviour for Cablix ERP tenant operations.

Invoices are tenant-owned financial records and must be tenant-scoped.

## Invoice Modes

The invoice module should support:

- Booking-based invoice
- Direct/manual invoice

Booking-based invoice is generated from an existing booking.

Direct/manual invoice is created without a booking when required for business use cases.

## Invoice Template

Use one common invoice template.

Use one common invoice item table.

Do not create separate invoice templates or separate item tables for:

- Outstation
- Local
- Package

Billing type can be used for reference and reporting but should not change the invoice item structure.

## Invoice Header

Header data should come from tenant settings, GST registration, invoice series, and company profile.

Read-only header fields:

- TAX INVOICE
- Company logo
- Company name
- Address
- Website
- Mobile numbers
- GST number
- HSN code
- Business category

Tenant may later support multiple GST registrations and invoice series.

## Invoice Numbering

Invoice number should be generated only when the invoice is finalized/generated.

Draft invoice should not consume invoice number.

Invoice number should lock after generation.

Recommended fields:

- invoice_series_id
- invoice_prefix
- invoice_number
- invoice_sequence
- financial_year
- generated_at

Invoice numbers must be unique per tenant and invoice series.

Recommended uniqueness:

```text
unique(tenant_id, invoice_series_id, invoice_number)
```

## Drafts

Draft invoice:

- Can be saved without invoice number.
- Can be edited.
- Can be previewed.
- Should not be treated as a legal/final tax invoice.
- Should not consume invoice sequence.

Draft status:

```text
Draft
```

## Finalization

Generate Invoice action should:

- Validate required fields.
- Assign invoice number.
- Lock invoice number.
- Mark status as Generated.
- Store generated timestamp and generated by user.
- Preserve invoice snapshot data.

Generated invoices should remain editable only through controlled edit/version rules.

If edit-after-generation is allowed, the system should record audit history.

## Cancellation

Generated invoices should not be hard deleted.

Cancellation should:

- Mark invoice status as Cancelled.
- Capture cancellation reason.
- Capture cancelled_at.
- Capture cancelled_by.
- Preserve original invoice data.

Cancelled invoice numbers should not be reused.

## Invoice Items

Use one generic invoice item structure:

- Date of Use
- Description
- Qty
- Unit
- Rate
- Amount

Date of Use may be:

- Single date
- Date range
- Blank for additional charges

If date range is displayed in compact invoice layout, the end date may appear on the next line.

Amount:

```text
Amount = Qty * Rate
```

Manual override may be allowed.

Unit options:

- KM
- Day
- Days
- Hour
- Hours
- Package
- Trip
- Night
- Actual
- Discount

Additional charges should use normal invoice rows:

- Toll Tax
- Parking
- Driver Allowance
- Service Charge
- Discount

## GST Rules

GST type options:

- No GST
- CGST + SGST
- IGST

If CGST + SGST:

```text
CGST = Taxable Amount * 2.5%
SGST = Taxable Amount * 2.5%
```

If IGST:

```text
IGST = Taxable Amount * 5%
```

Net payable:

```text
Net Payable = Taxable Amount + Total GST
```

GSTIN validation should be handled in GST registration settings.

GST registration may be:

- Regular
- Composition
- Unregistered
- Other

GSTIN is required for Regular and Composition registrations.

## GST Registration And Invoice Series

A tenant may have:

- One GST registration with multiple branches.
- Multiple GST registrations.
- Multiple branches mapped to one GST registration.
- Different invoice series for different GST registrations.

Inactive GST registrations should not be selectable for new invoice series.

Generated invoices should reference the GST registration and invoice series used at generation time.

## Invoice Preview And Print

Invoice preview and print should use A4-style layout with border.

Current invoice design direction:

- Lato font across invoice.
- Comfort Cars header name prominent.
- Bill To section and company details aligned as per latest template.
- Invoice number can appear near the TAX INVOICE header.
- Invoice details should include issue date, booking/reference, vehicle, and service city.
- Bank details and signature should use tenant settings.

Print layout should preserve invoice borders, spacing, table alignment, and totals.

## Invoice Actions

Invoice screen should support:

- Save Draft
- Preview
- Generate Invoice
- Print
- Download PDF
- Edit generated invoice if allowed by business policy
- Cancel

Generated invoice edit should be controlled and audited.
